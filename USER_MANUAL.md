# ChatGPT Exporter — User Manual

## 1. What it is

ChatGPT Exporter is a local tool for exporting ChatGPT conversations, Projects, and custom GPTs into a readable and reusable file structure.

The application runs on your own computer and provides a local web interface. An export can include:

- Raw JSON conversation data.
- Readable Markdown.
- Browseable HTML.
- Images and attachments.
- Files generated by ChatGPT and linked through `sandbox:/...`.
- Project resources.
- Basic custom GPT information.

The tool uses the ChatGPT session provided by the user to access the same internal endpoints used by the ChatGPT web application.

> The API used by this project is internal and unofficial. It may change at any time.

---

## 2. Starting the application

From the project directory:

```bash
npm start
```

or:

```bash
node server.js
```

The application starts a local server at:

```text
http://127.0.0.1:8523
```

and normally opens the browser automatically.

For additional diagnostics:

```bash
node server.js --debug
```

Debug mode writes a `debug.log` file.

> The log may contain conversation and file identifiers. Review it before sharing it.

---

## 3. Getting your ChatGPT session

The application temporarily needs the `accessToken` from an already authenticated ChatGPT session.

1. Sign in to ChatGPT normally.
2. Open:

   ```text
   https://chatgpt.com/api/auth/session
   ```

3. Copy the entire JSON shown on the page.
4. Paste it into the ChatGPT Exporter session field.

The application extracts:

```json
"accessToken": "..."
```

Treat this token as a sensitive credential and do not share it.

---

## 4. First export

In the web interface:

1. Paste the session JSON.
2. Select the output directory.
3. Review `Export options` if needed.
4. Click `Export conversations`.

The application first builds the required inventories and then downloads conversations that need to be created or updated.

During the process it shows:

- current conversation;
- progress;
- new conversations;
- updated conversations;
- resumed conversations that did not need downloading;
- failures;
- approximate processing rate.

---

## 5. Export directory structure

A typical export looks like this:

```text
chatgpt-export/
├── index.html
├── json/
├── markdown/
├── html/
├── files/
├── projects/
│   └── Project Name/
│       ├── project-info.md
│       ├── resources/
│       ├── json/
│       ├── markdown/
│       ├── html/
│       └── files/
├── archived/
│   ├── json/
│   ├── markdown/
│   ├── html/
│   └── files/
├── deleted/
│   ├── json/
│   ├── markdown/
│   ├── html/
│   └── files/
├── gpts/
└── logs/
```

`json/`
: Raw conversation data. It is also used by Smart Resume and Markdown regeneration.

`markdown/`
: Conversations converted to Markdown.

`html/`
: Conversations converted to HTML.

`files/`
: Images, attachments, and generated files associated with each conversation.

`projects/`
: Active Projects, Project resources, and their conversations.

`archived/`
: Conversations that are currently archived in ChatGPT.

`deleted/`
: Conversations that existed locally but no longer appear in the remote inventory.

`gpts/`
: Exported custom GPT information.

`logs/`
: Per-run export logs.

## 6. Active, archived, and deleted conversations

ChatGPT Exporter keeps three states separate.

### Active

Normal conversations are stored in the main directories or inside their corresponding Project.

### Archived

The application explicitly queries both inventories:

```text
is_archived=false
```

and:

```text
is_archived=true
```

Archived conversations are stored under:

```text
archived/
```

If an active conversation becomes archived, its JSON, Markdown, HTML, and files are moved together.

If it is later unarchived, it is moved back to the appropriate active location.

### Deleted

A local conversation is considered missing only after the required remote inventories have completed successfully.

Instead of deleting it from disk, ChatGPT Exporter moves it to:

```text
deleted/
```

JSON, Markdown, HTML, and the associated files directory are kept together.

`deleted/` therefore acts as a local historical trash/archive.

If a conversation later reappears remotely, it can be restored to its active location.

### Safeguards

Reconciliation into `deleted/` is not performed when the remote inventory cannot be considered complete, for example after certain errors or API rate limits.

---

## 7. Smart Resume

The exporter is designed to be run repeatedly against the same output directory.

For each conversation it compares the remote inventory entry with the local JSON copy.

### NEW

No local copy exists.

The conversation is downloaded and its output formats are generated.

### RESUMED

A local copy exists and does not need updating.

The conversation is not downloaded again.

### UPDATED

The conversation needs to be refreshed, for example because:

- the remote `update_time` is newer;
- the title changed;
- the local timestamp is missing or invalid;
- the conversation moved to a different export location.

Smart Resume uses `update_time` to decide whether a conversation needs to be updated.

The date filter in the UI uses `create_time`.

---

## 8. Rate limiting

Requests sent to ChatGPT are paced to reduce the risk of hitting usage limits. The current limiter starts ChatGPT API requests no faster than approximately one per second.

If ChatGPT responds with HTTP `429`:

- the exporter stops making new ChatGPT requests;
- it does not enter an automatic retry loop;
- the UI reports the export as **paused**, not successfully completed;
- processed and remaining conversation counts are shown when available;
- `Retry-After` is displayed when ChatGPT provides it;
- all data already saved remains on disk;
- a later run can continue through Smart Resume.

Downloads from external signed URLs are not treated as normal ChatGPT API requests.

The exact internal ChatGPT rate-limit policy is not documented by OpenAI. A community investigation in another exporter project suggests a token-bucket model with an initial capacity around 200–250 requests and a refill around one request per minute. Those numbers are empirical, may vary, and the source itself says they still need re-verification.

See [RATE_LIMITING.md](RATE_LIMITING.md) for the model, rationale behind the exporter's stop-on-first-429 behavior, and the external source.

## 9. Attachments, images, and filenames

Conversations may contain:

- user-uploaded documents;
- images;
- file citations;
- Project resources;
- files generated by ChatGPT.

When a file is downloaded successfully, it is stored in the corresponding `files/` directory.

Filenames are sanitized to remain compatible with Windows.

If two files resolve to the same local name, the exporter makes them unique to avoid overwriting data.

---

## 10. `.file-map.json`

A conversation file directory may contain:

```text
.file-map.json
```

This manifest stores the relationship between the original file identity and the actual local filename.

Example:

```json
{
  "version": 2,
  "files": {
    "file-abc123": "document.pdf",
    "sandbox:/mnt/data/report.zip": "report.zip"
  }
}
```

If a download fails, a `failed` section may also be present with the intended filename and error message.

The manifest is important because it allows Markdown links to be rebuilt later without guessing file identity from filenames.

---

## 11. ChatGPT-generated files (`sandbox:/...`)

ChatGPT can generate files and reference them through internal paths such as:

```text
sandbox:/mnt/data/report.zip
```

or:

```text
sandbox:/workspace/.../document.docx
```

During a normal export, ChatGPT Exporter attempts to resolve and download these files.

If the download succeeds:

- the file is stored in the conversation's local files directory;
- `.file-map.json` records the original `sandbox:/...` path;
- Markdown and HTML links are rewritten to the local file.

For example, an internal link may become something like:

```text
../files/2026-10-24_My conversation_ab12cd34/report.zip
```

### Old or expired generated files

Some historical `sandbox:/...` links may no longer be downloadable.

In that case:

- the conversation still exports successfully;
- the failure is recorded in the manifest;
- the exporter does not guess a local match by filename.

## 12. Generated Markdown

The Markdown renderer aims to preserve the readable, user-visible conversation.

It may include:

- title;
- user and assistant messages;
- code blocks;
- images and attachments;
- links;
- web sources;
- file citations;
- optional metadata;
- visible activity summaries;
- a versioned footer.

### Web sources

Modern ChatGPT web references are converted into normal Markdown links when possible.

At the end of a response with sources, the exporter may add:

```markdown
**Sources:**
- [Source title](https://example.com)
```

Duplicate URLs are removed.

The parameter:

```text
utm_source=chatgpt.com
```

is removed from exported source URLs.

### File citations

A file citation may appear as:

```markdown
[Source: document.pdf]
```

or, when a local copy is known through `.file-map.json`:

```markdown
[Source: document.pdf](../files/.../document.pdf)
```

### Activity summaries (Worked)

If enabled, visible activity summaries can be rendered as blocks such as:

```markdown
> **Worked**
>
> Ran 5 commands
```

This option does not export private chain-of-thought reasoning. It only represents visible activity-summary content present in the conversation data.

### Footer

Each generated Markdown file ends with a footer similar to:

```markdown
---

*Generated by [ChatGPT Exporter](https://github.com/moisescastellano/chatgpt-exporter) vX.Y.Z*
```

The version comes from `package.json`.

## 13. Markdown options

The `Export options` section includes several Markdown settings.

### Conversation metadata

Adds general conversation information such as:

- creation date;
- update date;
- export date;
- link to the original conversation.

### Message timestamps

Adds date and time information to messages.

### Model name

Shows the model name when that information is available.

### Activity summaries (Worked)

Includes the visible activity summaries described above.

### Date format

Available options:

```text
ISO — YYYY-MM-DD
European — DD/MM/YYYY
```

### Conversation branch

ChatGPT may preserve multiple branches of a conversation.

`Current branch`
: Exports the branch leading to `current_node`.

`All branches`
: Walks every available branch.

If the current branch cannot be determined reliably, the renderer may fall back to all branches to avoid losing content.

### User label / Assistant label

These settings let you customize the headings used for both participants.

Markdown preferences are stored locally in the browser.

---

## 14. Regenerate Markdown

The button:

```text
Regenerate Markdown
```

rebuilds `.md` files using only JSON and files already present in the export.

It does not require the session token and does not contact ChatGPT.

This is especially useful for:

- changing Markdown options;
- changing the date format;
- changing participant labels;
- switching between current branch and all branches;
- applying renderer improvements to previously exported conversations.

Regeneration scans:

- active root conversations;
- Project conversations;
- `archived/`;
- `deleted/`.

When `.file-map.json` exists, it is used to reconstruct links to attachments and `sandbox:/...` files correctly.

---

## 15. HTML and `index.html`

In addition to individual HTML files, the export generates:

```text
index.html
```

This file provides local browsing of the exported data.

The index includes the different export areas, including archived and deleted conversations when they exist.

Generated HTML uses downloaded local files whenever the required mapping is available.

---

## 16. Projects

Each Project gets its own directory under:

```text
projects/
```

It may contain:

```text
project-info.md
resources/
json/
markdown/
html/
files/
```

`project-info.md` contains the available Project information.

`resources/` contains files attached directly to the Project.

Active Project conversations are stored inside the Project.

### Selecting specific Projects

Projects default to **all Projects**.

Use **Choose...** next to the Projects option to load the Project list and select only the Projects you want to export. The dialog supports selecting all Projects, clearing the selection, or choosing individual Projects.

The selection controls which Projects have their metadata, resources, and full conversations exported. It does **not** redefine the remote inventory: the exporter still accounts for all Projects when required for active/archived/deleted reconciliation. Therefore, leaving a Project unchecked does not cause its existing local conversations to be treated as deleted.

If a conversation becomes archived or deleted, that state is represented through the global `archived/` or `deleted/` areas.

## 17. Custom GPTs

When GPT export is enabled, basic custom GPT information is written under:

```text
gpts/
```

Depending on what the API returns, this may include:

- name;
- description;
- instructions;
- conversation starters;
- configured tools;
- visibility.

## 18. Date filtering

The interface supports:

```text
From
Until
```

The date filter is applied to the conversation creation date (`create_time`).

Leaving both fields empty exports all dates.

Inventory logic used to classify active, archived, and missing conversations remains separate from the final date filtering of conversations to process.

## 19. Output formats

### JSON

Stores the original conversation data.

The local JSON also plays an internal role in Smart Resume and Markdown regeneration.

### Markdown

Readable and reusable text output.

### HTML

Browseable output intended for local viewing.

### ZIP

The exporter can optionally create a ZIP containing the generated export data.

## 20. Keep computer awake

The option:

```text
Keep computer awake during export
```

tries to prevent the computer from sleeping during long exports.

The implementation depends on the operating system.

Failure of this optional feature should not prevent the export itself.

---

## 21. Exporting and regenerating are different operations

### Export conversations

A normal export may:

- build inventories;
- download conversations;
- update conversations;
- download attachments;
- download `sandbox:/...` files;
- reconcile active / archived / deleted states.

### Regenerate Markdown

Markdown regeneration is completely local:

- reads existing JSON;
- reads `.file-map.json`;
- generates Markdown;
- does not download conversations;
- does not download files;
- does not contact ChatGPT.

A `sandbox:/...` file that was never downloaded cannot be recovered by `Regenerate Markdown`.

---

## 22. After an interrupted export

If an export is interrupted, simply run it again against the same output directory.

Smart Resume reuses what has already been saved.

There is no need to start over.

If the interruption was caused by HTTP `429`, the UI reports the run as paused. Wait before starting another export, reuse the same output directory, and let Smart Resume continue from the data already saved. If ChatGPT supplied a `Retry-After` value, the UI displays it.

---

## 23. Checking an export

After an important export, it is useful to review:

1. The final UI message.
2. The `logs/` directory.
3. A recent Markdown conversation.
4. At least one attachment or generated file.
5. `archived/` if conversations were archived.
6. `deleted/` if conversations were removed remotely.
7. The local `index.html` viewer.

If a specific file failed, also inspect the relevant `.file-map.json`.

---

## 24. Known limitations

- The tool depends on undocumented internal ChatGPT endpoints.
- Those endpoints can change without notice.
- Old `sandbox:/...` links may have expired.
- Not every internal message type necessarily has a useful Markdown representation.
- ChatGPT's internal data structures may change over time.
- Reaching an API rate limit can interrupt an export run.
- The token-bucket figures discussed in `RATE_LIMITING.md` are community observations, not an official OpenAI contract.
- This tool does not replace OpenAI's official data export mechanism.

---

## 25. Security

Treat the ChatGPT `accessToken` as a sensitive credential.

Recommended practices:

- do not commit it;
- do not store it in documentation;
- do not send it through email or messaging;
- review `debug.log` before sharing it;
- keep export directories private if they contain personal information.

ChatGPT Exporter does not need to send your exported data to a third-party service in order to perform the export.

---

## 26. Recommended workflow

To keep a local backup up to date:

1. Run ChatGPT Exporter periodically.
2. Reuse the same output directory.
3. Let Smart Resume download only new or changed conversations.
4. Review `archived/` and `deleted/` after important account changes.
5. Use `Regenerate Markdown` when only renderer behavior or Markdown options changed.
6. Keep the JSON files if you want to regenerate Markdown later.

---

## 27. Quick reference

For a normal update:

```text
1. npm start
2. open /api/auth/session
3. copy and paste the session JSON
4. select the same export directory
5. click Export conversations
```

To regenerate Markdown only:

```text
1. npm start
2. select the export directory
3. adjust Markdown options
4. click Regenerate Markdown
```

No ChatGPT session is required for local Markdown regeneration.
